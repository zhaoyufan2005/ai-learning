# Concept Learner — 概念学习资料生成器

## 用途

接收任何概念名称（技术、科学、人文、商业等领域均可），产出自包含的 HTML 学习资料，保存到仓库的 `learning-materials/` 目录下。

## 触发方式

用户给出一个概念名称并要求生成学习资料，例如：

- "帮我学习『梯度下降』"
- "生成一份『边际效用』的 HTML 学习资料"
- "我想搞懂 CAP 定理，出一份带自测题的资料"

## 输出规范

### 1. 文件位置与命名

- 输出目录：`learning-materials/`
- 文件名：概念的英文或拼音 slug，小写、连字符分隔，如 `gradient-descent.html`、`cap-theorem.html`
- 若概念为中文专名（如"阴阳五行"），可用拼音 slug（`yin-yang-wu-xing.html`）

### 2. HTML 结构（必须包含以下五个部分）

```html
<!DOCTYPE html>
<html lang="zh-CN">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>概念名称 - 学习资料</title>
  <style>/* 内联样式，无外部依赖，单文件可用 */</style>
</head>
<body>
  <header>概念名称 + 一句话定义</header>
  <main>
    <section id="objectives">① 学习目标</section>
    <section id="explanation">② 概念解释（分层递进）</section>
    <section id="examples">③ 案例</section>
    <section id="quiz">④ 自测题</section>
    <section id="references">⑤ 参考来源</section>
  </main>
</body>
</html>
```

### 3. 各部分内容要求

**① 学习目标（objectives）**
- 3–5 条，用"能够……"的行为动词开头（解释、区分、应用、分析）
- 覆盖布鲁姆分类的低阶到高阶：理解 → 应用 → 分析

**② 概念解释（explanation）— 分三层递进**
- **一句话版本**：30 字以内，给完全的门外汉
- **直观版本**：用类比、比喻、生活场景解释，不出现公式和专业术语（或出现即立刻解释）
- **严谨版本**：准确定义、关键术语、必要公式/机制、边界条件与常见误解
- 涉及发展史的概念可加一小节"来龙去脉"

**③ 案例（examples）**
- 至少 3 个案例，按难度递进：日常案例 → 行业/学科案例 → 进阶或反例
- 每个案例包含：情境描述、概念如何应用、结论
- 有反例（"什么不是这个概念"）最佳，用于澄清边界

**④ 自测题（quiz）**
- 5–8 题，混合题型：选择题、判断题、简答题
- 每题附答案与解析，默认收起（用 `<details><summary>` 实现），标注考察哪条学习目标
- 至少 1 题是应用型场景题（给情境判断概念是否适用）

**⑤ 参考来源（references）**
- 3–6 条，优先：经典教材、权威百科（如 Stanford Encyclopedia、维基百科）、原始论文、官方文档
- 如实际检索过网络来源，给出真实链接；未检索时给出可查证的文献名（书名、作者、章节），**不得编造 URL**

### 4. 视觉与交互要求

- 单文件自包含：所有 CSS/JS 内联，不引用外部资源（CDN、字体、图片均不用）
- 响应式布局，移动端可读
- 自测题答案用 `<details>` 折叠；可加"显示全部答案"按钮
- 配色简洁（浅色主题），用少量高亮色标注关键术语
- 顶部加一个简单的目录导航（锚点跳转）

## 执行流程

1. **解析概念**：确认概念名称、所属领域、用户当前水平（如未说明，默认"有通识背景的初学者"）
2. **知识准备**：如概念较新或拿不准，先用网络搜索核实关键事实，避免幻觉
3. **生成 HTML**：按上述结构和要求写入 `learning-materials/<slug>.html`
4. **自检**：五个部分是否齐全？解释是否分层？自测题是否附答案解析？参考来源是否真实可查？
5. **交付**：用文件展示工具把生成的 HTML 呈现给用户预览，并简述覆盖了哪些内容

## 约束

- 概念有争议或多定义时，说明主流定义并列出分歧，不擅自站队
- 公式必须用 HTML/Unicode 正确排版（可用行内样式模拟，不依赖 MathJax CDN）
- 不编造引用链接；不确定的 URL 就写文献名而非假链接
- 输出语言跟随用户提问语言（默认简体中文，保留必要的英文术语并附中文注释）
